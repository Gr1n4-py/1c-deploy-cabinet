## Проект

**Личный кабинет (Electron + TS SPA) для развертки и управления 1С-проектами.**
Пользователь деплоит базы 1С из .dt/шаблонов в готовые проекты для AI-разработки
(исходники конфигурации в src/cf, расширения в src/cfe, публикация в Apache,
MCP-инструменты, правила для AI-агентов), а кабинет — GUI для этого: мастер
развертки с живым мониторингом, карточки проектов, настройки, запуск инструментов.

- Репозиторий: `C:\1C_Bases\AI\cabinet` (git, ветка main,
  https://github.com/Gr1n4-py/1c-deploy-cabinet).
- Портфель решений: `docs/decisions.md` (D1–D14), дорожная карта — п.7.
- Как работает каждое место кода — `docs/functionality.md` (обновлять после
  изменений!).

## Ловушки окружения (ПРОВЕРЕНО, не игнорировать)

- Node — портативный: `C:\Users\Н_Вадим\Desktop\НаумовЗадания\полезные
  обработки\ai\nodejs` (добавлять в PATH сессии), npm только `npm.cmd`.
- **Пересборка exe = EBUSY на win-unpacked**, если какой-то процесс держит
  каталог как рабочий (CWD): сам запущенный кабинет, LibreOffice, httpd,
  запущенные runner'ом без WorkingDirectory (исправлено в Core.Publish.psm1).
  Сначала закрыть кабинет и 1С-окна, затем `npm.cmd run app:build`. Диагностика
  «кто держит»: перебор процессов с чтением PEB (NtQueryInformationProcess) —
  скрипт лежал в %TEMP%\kilo\find-cwd.ps1, удален, восстановить по истории
  сессии. Старый залоченный build/exe не трогать (вывод сборки в build/app/).
- **spawn аргументов 1cv8 из Node:** ключ и значение — РАЗНЫЕ токены
  (`/F`, путь), НЕ склеивать `/F"путь"` — Node экранирует кавычки, 1cv8
  не распознает путь и открывает `C:\1Cv8.1CD` (ошибка режима доступа).
- **1cv8c.exe не понимает DESIGNER** — молча открывает Предприятие;
  конфигуратор запускать только через лаунчер 1cv8.exe. Лаунчер сам запускает
  per-user x86-клиент из %LOCALAPPDATA%\Programs\1cv8_x86 — для 64-битного
  Предприятия запускать 1cv8c.exe из C:\Program Files\1cv8\<версия>\bin.
- **.ps1/.psm1 с кириллицей — только UTF-8 С BOM** (PS 5.1 без BOM читает как
  ANSI). Файлы JSON/env — UTF-8 БЕЗ BOM.
- Из терминалов VS Code перед запуском electron снимать
  `ELECTRON_RUN_AS_NODE` (иначе Electron стартует как голый Node).
- spawn powershell из Electron: `detached: true` + `windowsHide: true` ВМЕСТЕ
  = тихая смерть процесса. Только windowsHide + stdio в файл.
- PS 5.1: в однострочном массиве `@('a', 'x=' + $y)` запятая ломает конкатенацию.
- `Element.replaceWith()` у узла без родителя — молча no-op (не использовать
  до добавления в DOM).
- Удаление каталогов кабинет защищает черным списком (корень диска,
  `C:\1C_Bases\AI`, `runs\`, DATA_DIR) — POST /api/projects/delete вернет 400.

## API шаблонов конфигураций (новое, 2026-11-09)

- `GET /api/templates` — реестр установленных шаблонов: сканирование
  `tools.templatesRoot` (настройка «Каталог шаблонов конфигураций», дефолт
  `C:\1C_Bases\SHABLONI`) → `{ root, templates: [{ vendor, name, version,
  dir, cfPath, mft, sources }] }`; источники — секции [ConfigN] из 1cv8.mft
  (demo = «демо» в Catalog) или все *.dt без mft.
- `POST /api/templates/install { zipPath }` — установка шаблона из скачанного
  zip: распаковка (Expand-Archive), поиск 1cv8.mft/1Cv8.cf до 3 уровней,
  копирование в дерево каталога шаблонов (имена из mft). «Только setup.exe»
  → 400 (тихий ключ не определен).
- `POST /api/deploy` — манифест теперь содержит `dtPath` ИЛИ `templateCfPath`
  (ровно один; валидация существования файла); runner шаг 04 ветвится:
  dt → New-CoreInfobaseFromDt, cf → New-CoreInfobaseFromCf
  (`ibcmd create --load=<cf> --apply --force`).

## API карточек проектов (новое, 2026-11-03…06)- `POST /api/projects/info { projectDir }` — собрать и записать в реестр info +
  infoUpdatedAt. Транзакция: полная сборка в памяти до записи. Источники:
  `src/cf/Configuration.xml` (читается голова 256 КБ: Name/Synonym/Version/
  Vendor/режим совместимости), `src/cfe/*/Configuration.xml` (расширения:
  имя/синоним/версия/ConfigurationExtensionPurpose; purpose=Patch → строка
  «Патчи»), `.dev.env` (INFOBASE_KIND, INFOBASE_PATH / INFOBASE_SRVR+REF —
  задел под серверный режим, IB_USER, PLATFORM_VERSION, PLATFORM_PATH,
  INFOBASE_PUBLISH_URL). Ограничение: читает текущую выгрузку — изменения в ИБ
  без дампа cf/cfe не видны.
- `POST /api/projects/open { projectDir, target: vscode|designer|enterprise }`:
  vscode → `Code.exe -r <dir>` (окно переиспользуется); **designer** →
  лаунчер `1cv8.exe DESIGNER` (1cv8c.exe DESIGNER не понимает); **enterprise**
  → толстый клиент `1cv8c.exe` напрямую из `C:\Program Files\1cv8\<версия из
  карточки>\bin` (64-бит, лаунчер иначе подменяет на x86) → фолбэк
  `PLATFORM_PATH\bin` из .dev.env → настройки кабинета → автопоиск. Ключи —
  отдельными аргументами: `/F <путь>` | `/S <srvr\ref>`, `/N <user>`,
  `/P <pwd>` (из .dev.env). cwd запуска — каталог проекта (дампы 1cv8 не
  засоряют папку exe). В ответе arch (только для прямого 1cv8c.exe), тост
  показывает разрядность.
- `POST /api/projects/check-publish { publishUrl }` — **реальная проверка**:
  один локальный HTTP GET на URL публикации (таймаут 4 с; 2xx–4xx = доступна,
  5xx/обрыв/таймаут = нет). Фронт: точка статуса в строке публикации карточки
  (проверка запускается при отрисовке списка).
- GET /api/projects отдает записи реестра вместе с info/infoUpdatedAt.
