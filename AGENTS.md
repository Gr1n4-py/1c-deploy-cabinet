# AGENTS.md — правила для ИИ-агентов в этом проекте

Файл читается агентами автоматически. Нарушение этих правил — ошибка агента.

## 1. Жёсткие ограничения

1. **Ничего не скачивать и не устанавливать без явного согласия пользователя.**
   Это включает: npm-пакеты (кроме `npm install` по уже изменённому пользователем package.json),
   скачивание exe/zip с сайтов, winget/любые установщики, обновления инструментов,
   «заодно» подтянуть какой-то CLI. Сначала короткий вопрос → согласие → действие.
   Уже согласованные инструменты перечислены ниже в «Окружении» — их переустановка/обновление тоже требует вопроса.
2. **Не менять ничего вне проекта** без спроса: глобальный git config, конфиги PortableGit
   и пользовательских инструментов, системные настройки, файлы в других папках.
3. **Секреты** (токены, пароли, .env) — не коммитить, не писать в код и в логи.
   Учетные данные git — только через credential helper / хранилище Windows.
4. **Файлы вне каталога проекта** не создавать, не перемещать и не удалять без спроса.
5. Неоднозначное действие (удаление файлов, выход за рамку задачи, изменения в
   `C:\1C_Bases\AI\script` — там рабочие скрипты развертки) — сначала короткий вопрос.

## 3. Процесс работы

- Перед каждым push: `npm.cmd run build` должен проходить без ошибок (tsc strict + vite build).
- Стиль коммитов: `feat:/fix:/chore:/docs:` + краткое описание, при необходимости тело со списком.
- Версионирование: `main` — рабочая ветка; теги `vX.Y.Z` по этапам дорожной карты
  (docs/decisions.md, п.7); ветки `feat/*` под крупные задачи.
- Любое изменение архитектурных решений — фиксировать в `docs/decisions.md`.
- Правила кода — в README.md («Правила кода»): классы вместо ID в стилях, JS-хуки `data-ref`,
  пользовательский ввод в DOM только через `textContent`, цвета/отступы через токены tokens.css.
