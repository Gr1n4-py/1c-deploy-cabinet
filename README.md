# 1C Deploy Cabinet

Личный кабинет в браузере для развертки и управления 1С-проектами:
список проектов, визард новой развертки (.dt → файловая/серверная база),
мониторинг прогонов, управление публикациями, подключение AI-агента и MCP.

Архитектура и принятые решения: [docs/decisions.md](docs/decisions.md) — читать первым делом.

## Стек

| Слой | Технология |
|---|---|
| Frontend | TypeScript + Vite (vanilla, без фреймворка) |
| Backend (этап 1) | PowerShell 5.1 + Pode, localhost, без прав администратора |
| Данные | Файлы проекта: `data/users.json`, `data/registry.json` (сейчас — localStorage прототипа) |

## Структура

```
index.html            — каркас (только #app + точка входа)
src/
  main.ts             — регистрация маршрутов, запуск роутера
  router.ts           — минимальный hash-роутер
  types.ts            — общие типы (контракты данных)
  lib/storage.ts      — хранилище прототипа (localStorage) -> заменяется на api/
  pages/              — страницы: login, desktop (новая страница = новый модуль + registerRoute)
  components/         — переиспользуемые блоки: topbar, toast
  styles/             — tokens.css (дизайн-токены), base.css, стили по компонентам/страницам
  api/                — обёртки над будущим Pode-API
docs/decisions.md     — контекст проекта, решения D1–D9, дорожная карта
prototype-legacy/     — исторический одностраничный прототип (до рефакторинга)
```

## Правила кода

- Стили — по классам, ID не использовать для стилизации; JS-хуки — `data-ref="..."`.
- Пользовательский ввод в DOM — только через `textContent`.
- Цвета/отступы — только дизайн-токены из `src/styles/tokens.css`.
- Данные через `src/lib/storage.ts` (контракт = будущий API), страницы DOM напрямую не хранят.
